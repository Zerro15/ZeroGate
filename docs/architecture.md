# Архитектура ZerroGate

## Общая идея
ZerroGate разделён на два мира: backend на FastAPI и клиент на Flutter. Backend отвечает за пользователей, устройства, профили подключений и телеметрию. Клиент — за красивый интерфейс и удобное управление.

## Backend
- **Слои**: API (FastAPI роуты), схемы (Pydantic), бизнес-логика (services), доступ к данным (SQLAlchemy ORM).
- **БД**: SQLite по умолчанию, можно заменить на PostgreSQL, сменив `database_url` в `.env`.
- **Аутентификация**: JWT на базе `python-jose`, демо-админ создаётся при старте.
- **Телеметрия**: простые записи о действиях устройств и ошибках через модель `LogEntry`.

## Клиент
- **State management**: Riverpod — простые провайдеры для API-клиента и состояния.
- **Слои**: `data` (работа с Dio и хранением токена), `domain` (провайдеры, логика), `presentation` (экраны).
- **UI**: минималистичные экраны логина и дашборда, готовые к расширению.

## Потоки данных
1. Пользователь вводит адрес сервера и логин в приложении.
2. Клиент вызывает `/api/auth/demo-login`, получает JWT и сохраняет его.
3. Клиент запрашивает `/api/status` и выводит информацию.
4. Дополнительно можно расширять запросы для устройств, профилей и логов.
