# Архитектура ZeroGate

## Общая идея
ZeroGate разделён на два мира: backend на FastAPI и клиент на Flutter. Backend отвечает за пользователей, устройства, профили подключений и телеметрию. Клиент — за понятный интерфейс и управление.

## Backend
- **Слои**: API (FastAPI роуты), схемы (Pydantic), бизнес-логика (services), доступ к данным (SQLAlchemy ORM).
- **БД**: SQLite по умолчанию, можно заменить на PostgreSQL, сменив `DATABASE_URL` в `.env`.
- **Аутентификация**: JWT на базе `python-jose`, демо-админ создаётся при старте.
- **Телеметрия**: простые записи о действиях устройств и ошибках через модель `LogEntry`.

## Клиент
- **State management**: Riverpod — провайдеры для API-клиента и состояния.
- **Слои**: `data` (работа с Dio и хранением токена), `domain` (use-cases, сущности), `presentation` (экраны, провайдеры).
- **UI**: минималистичные экраны логина и статуса, заготовки для устройств/профилей/логов.

## Потоки данных
1. Пользователь вводит адрес сервера и логин в приложении.
2. Клиент вызывает `/api/auth/login`, получает JWT и сохраняет его.
3. Клиент запрашивает `/api/status` и выводит информацию.
4. Дополнительно можно расширять запросы для устройств, профилей и логов.
